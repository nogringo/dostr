## 0.1.0

 - Initial release, moved out of the `ndk_flutter` package: `WebSigner`, `WebEventVerifier`, and `WebSignerFactory`, the web factory that `ndk_flutter` called `NdkEventSignerFactory`. `WebEventSigner` of `ndk_flutter` is now `WebSigner`, after the `NostrSigner` it implements.
 - `encryptNip44` and `decryptNip44` take `recipientPubkey` and `senderPubkey`, as in `NostrSigner`, instead of `recipientPubKey` and `senderPubKey`.
 - As in `NostrSigner`, `encrypt` and `decrypt` are now `encryptNip04` and `decryptNip04`, with named parameters, the four encryption methods return a `Future<String>` instead of a `Future<String?>`, `canSign` is a getter, `getPublicKey()` is the `publicKey` getter, and `requiresInteractiveSigning`, `requiresSignerNetwork` and `signerTransportRelayUrls` are gone.
 - `encryptNip44` and `decryptNip44` handle messages longer than 65535 bytes, up to 4294967295, with the 6-byte length prefix that NIP-44 added in nostr-protocol/nips#1907.
 - `decryptNip44` rejects a payload whose padding is not the one NIP-44 requires, and checks the payload size as NIP-44 says.
 - `decryptNip04` and `decryptNip44` throw when the plaintext is not valid UTF-8, as `dostr_nip44` does, instead of replacing the invalid bytes with U+FFFD.
 - `WebSigner` keeps the NIP-44 conversation keys of its last 256 peers, so `encryptNip44` and `decryptNip44` run the key agreement once per peer instead of once per message.
 - **BREAKING** `WebSigner(privateKey)` derives its public key and `WebSigner.readOnly(publicKey)` knows only a public key, as for `Bip340Signer`, instead of `WebSigner(privateKey:, publicKey:)`, which signed with a public key that might not be the one of the private key. Both fields are final.
 - As in `LocalSignerFactory`, `WebSignerFactory.create` takes the private key alone, `readOnly` takes a public key, `generateKeyPair` returns a `KeyPair`, and `derivePublicKey` is gone.
 - `WebSigner` and `WebSignerFactory.create` throw a `FormatException` for a private key that is not one, as `Bip340Signer` does, instead of reading `1z` as `01`, and `WebSigner.readOnly` and `WebSignerFactory.readOnly` throw one for a public key that is not 64 lowercase hex characters, as `LocalSignerFactory` says.
 - As `NostrSigner` says, an encryption or a decryption that fails throws a `SignerRequestFailedException`, `sign` throws an `ArgumentError` for an event of another pubkey, and every operation of a read-only `WebSigner` throws a `StateError`.
 - NIP-04 and NIP-44 run on @noble/ciphers and @noble/hashes instead of the Web Crypto API, so they also work on a page served over plain http, where `crypto.subtle` does not exist.
 - `WebEventVerifier` is const and checks the id with `Nip01Event.hasValidId`, as `Bip340EventVerifier` does, instead of hashing the event again in JS. On other platforms, its `verify` throws the `UnsupportedError` instead of its constructor.
 - The JS bundle is injected on first use instead of when a class is created, and a `StateError` says so when it did not run, as under a Content-Security-Policy that blocks inline scripts. It is injected once only, so that each call under such a policy does not add a script to the page.
 - **BREAKING** The JS bundle defines `DostrNoble` instead of `NostrCrypto`, so that the one of `ndk_flutter` or of another library is not taken for it, and no longer defines `NostrCryptoModule`.
 - The JS bundle carries a version, a hash of the files it is built from, and the classes throw a `StateError` when the page loaded a bundle of another version, as a `nostr_crypto.js` not copied again after an upgrade.
 - `WebSignerFactory.generateKeyPair` draws again a private key that is not one, as `Bip340.generateKeyPair` does, instead of throwing a `FormatException`.
 - The JS bundle carries the full MIT license of @noble/hashes, @noble/ciphers and @noble/curves, instead of the one-line notices of @noble/ciphers and @noble/curves only.
 - `decryptNip04` and `decryptNip44` read base64 as `dostr_nip44` does, with the rules of Dart's `base64.decode` instead of those of `atob`: whitespace, a missing padding and stray bits before the padding fail, NIP-04 also takes the URL-safe alphabet and a `%3D` padding, and NIP-44 takes standard base64 only.
 - `decryptNip04` rejects a payload with more than one `?iv=`, as `dostr_nip44` does.
 - The classes work in a Web Worker that loads the JS bundle with `importScripts`, and throw a `StateError` that says so when it did not, instead of a `TypeError`.
