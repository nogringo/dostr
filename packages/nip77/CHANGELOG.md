## 0.1.0

 - Initial release, moved out of the `ndk` package.
 - `Nip77.reconcile` takes its `relayUrl` as a `RelayUrl`, from `dostr_core`, and no longer throws an `ArgumentError` for a url that is not a relay's. `Nip77Response` and the exceptions give theirs as a `RelayUrl` too.
 - Logs with [`logging`](https://pub.dev/packages/logging), under the name `dostr_nip77`, instead of the logger of `ndk`: nothing is printed until the app listens to `Logger.root.onRecord`.
 - **BREAKING** `Nip77` takes only `loadEventIds`, and `localIds` gives each id with its creation time, so `loadEvent` and `Nip77LoadEvent` are gone. An id the cache did not hold used to be reconciled at created_at 0, and could come back in both `needIds` and `haveIds`.
 - **BREAKING** Every failure of `reconcile` is a `Nip77Exception`. A NEG-ERR, or a CLOSED that asks for no identity, fails with `Nip77RefusedException`, whose `code` gives the `blocked` or `closed` prefix NIP-77 suggests and `maxRecords` the limit a `blocked` refusal gives. It used to be a plain `Exception`, or a `Nip77NotSupportedException` for a NEG-ERR naming `CLOSED` in capitals, which no relay following NIP-77 sends. A connection that does not open fails with `Nip77ConnectionException`, and a NEG-MSG the codec cannot read with `Nip77MalformedMessageException`, after a NEG-CLOSE.
 - A NOTICE that looks like a refusal of NIP-77 only fails the negotiations of its connection still waiting for their first answer, with `Nip77NotSupportedException`. It used to fail every negotiation on that relay with a plain `Exception`, those already exchanging rounds included.
 - Each reconciliation gets a random subscription id. It used to be the clock in microseconds, which on the web only changes every millisecond, so reconciliations started together could share one and end each other.
 - **BREAKING** `needStream` and `haveStream` are single-subscription streams that keep every id until they are listened to, and close whatever the outcome. They were `BehaviorSubject`s, which gave a late listener only the last id. `rxdart` is no longer a dependency.
 - `Nip77Result.isComplete` is false for a reconciliation that `close` or `closeAll` ended before it converged.
 - `reconcile` keeps each NEG-MSG within `frameSizeLimit` bytes before hex encoding, 60000 by default, as the frame size limit of the reference implementation does, and `NegentropyEncoder.reconcile` and `respond` take it too. A larger difference takes more rounds instead of one message a relay may refuse.
 - `NegentropyEncoder` no longer sorts the list it is given, and a reconciliation sorts its local events once instead of every round, as `prepareNegentropyItems`, now exported, lets any caller do. Both hex conversions run on code units.
 - **BREAKING** `NegentropyEncoder` throws a `FormatException` for a message, varint or bound it cannot read, and `hexToBytes` for an odd length or a sign, which it used to read as a digit. It threw an `ArgumentError`, now kept for a wrong argument of the caller, such as an id that is not 64 hex digits in `NegentropyItem.fromHex`. `createInitialMessage` no longer takes an id size, which could only be 32.
 - A refusal moves a negotiation to a connection bound to an identity only when its reason starts with `auth-required`, as for a REQ. One that only contained `auth-required` or `restricted` did too, and under `AuthPolicy.allow` revealed the identity to a relay that never asked for it. A `restricted` refusal fails with `Nip77RefusedException`, without authenticating again.
 - A reconciliation whose connection drops or is closed fails at once with `Nip77ConnectionException`, whose `lost` is true. It used to wait for its timeout, and fail with `Nip77TimeoutException`.
 - `reconcile` throws an `ArgumentError` for a `localIds` entry whose id is not 64 hex digits or whose creation time is out of range, before anything is sent.
 - `Nip77.dispose` ends every reconciliation, as `closeAll` does, and stops listening to the `RelayManager`.
