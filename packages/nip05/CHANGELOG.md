## 0.1.0

 - Initial release, moved out of the `ndk` package. `Nip05Usecase` is now `Nip05Resolver`, and takes an optional `Nip05Cache` as `cache` instead of `database`: without one, it keeps what it resolved in memory. `Nip05Model` is gone: `Nip05HttpRepositoryImpl`, now `HttpNip05Repository`, returns a `Nip05`, and takes an `http.Client` as `client` instead of an `HttpRequestDS` as `httpDS`. The constants are in lowerCamelCase: `NIP_05_VALID_DURATION` is `nip05ValidDuration`.
 - `Nip05` is immutable and holds only what the domain gives. `pubKey` is now `pubkey`, never null and in lowercase hex, `relays` are `RelayUrl`s of `dostr_relay_url`, which this package exports, and `valid`, `networkFetchTime` and `copyWith` are gone. `toJson` and `fromJson` turn it into JSON and back.
 - `Nip05Cache` saves `Nip05Record`s, which hold the identifier, its `Nip05` or null when the domain has no such name, and when it was fetched.
 - `check` returns a `Nip05CheckResult`: `Nip05Verified`, `Nip05Mismatch` with what the address points to, `Nip05NotFound`, or the `Nip05ResolveError` that kept it from checking, where it returned a `Nip05` whose `valid` was false for a mismatch, a missing address and an error alike. It compares the pubkey whatever its case, and throws an `ArgumentError` for one that is not in hex, such as an npub.
 - `resolve` returns a `Nip05ResolveInvalidResponse` when the `nostr.json` gives something other than a hex pubkey for the name, such as an npub, and reads a missing or mistyped `relays` as none, where it failed the whole resolution. It normalizes the relays with `RelayUrl.tryParse`, keeps each once and drops those it refuses. It finds a name that `names` gives in another case, since NIP-05 names are case-insensitive.
 - An address that is not a NIP-05 identifier, such as one whose name holds a character outside `a-z0-9-_.` or whose domain is not a host name with at least one dot, such as a bare `bob`, is a `Nip05NotFound` and sends no request, where some came back as a `Nip05ResolveInvalidResponse` and others reached the network. An empty one is a `Nip05NotFound` too, where `resolve` and `check` threw an `Exception`.
 - `resolve` and `check` take an `abortTrigger`, which ends that call alone with a `RequestAbortedException`. `abortPending()` ends them all, and `close()` also closes the client the resolver made, after which `resolve` and `check` throw a `StateError`. `Nip05Resolver` takes an optional `httpClient`, or a `nip05Repository` instead, and `Nip05Repository` is an interface whose `fetchNip05` takes the `abortTrigger` too.
 - An error of the `Nip05Cache` reaches the caller of `resolve` and `check`, where a failed save came back as a `Nip05ResolveNetworkError`.
