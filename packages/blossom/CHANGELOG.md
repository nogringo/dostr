## 0.1.0

 - Initial release, moved out of the `ndk` package. Build `Blossom` from the accounts, the signer factory, the `AuthHandler` and a function that reads a user's server list, and `Files` from a `Blossom`.
 - `BlossomUserServerList`, which publishes the server list of the logged account (kind 10063), moved here from `ndk` too. It takes a callback to publish instead of `Broadcast`, and any `AuthAccounts` instead of `Accounts`, and `publishUserServerList` completes with whatever `publish` returns, so this package does not depend on `dostr_core`. Its `getUserServerList` is gone: read a user's server list with `BlossomServersFetcher` and `blossomServersOf`, from `dostr_fetchers`.
 - Compared with the `ndk` version: `BLOSSOM_AUTH_EXPIRATION` became `Blossom.defaultAuthExpiration`, and the `authExpiration` constructor parameter sets it. `BlobNip94.dimenssions` became `dimensions`, and `NdkFile` became `BlossomFile`, without its `size`. A read that no server served throws a `BlossomRequestException`. `BlossomRepository` takes `serverMediaOptimisation` like the usecases, and `BlossomRepositoryImpl`, `FileIO` and `createFileIO` are no longer exported.
 - It exports `dostr_blossom_url`. Every operation, read or write, normalizes the blob url, `serverUrls`, `targetServerUrls` and the server list with `BlossomServerUrl.tryParse`, so it talks to each server once however they spell it, and skips the urls it refuses, such as one with user info, which can hide the real host. `BlossomRepository` takes them as `BlossomServerUrl`s, and `BlobUploadResult.serverUrl`, `BlobUploadCheck.serverUrl`, `BlobDeleteResult.serverUrl`, `BlossomHashMismatchException.serverUrl` and the keys of `BlossomRequestException.errors` are `BlossomServerUrl`s too. `BlobUploadProgress.currentServer` is a `BlossomServerUrl?`: null while hashing and in the progress about no server, such as the first and the last of an upload, where it was an empty string.
 - `BlossomUserServerList.publishUserServerList` publishes the urls normalized, each once, and throws a `FormatException` for one that is not a server url.
 - `Blossom.report` names the server normalized, and throws a `FormatException` for a url that is not a server url.
 - `Files` reads a blossom url from its own server first, so the url alone is enough. A read given both `serverUrls` and `pubkeyToFetchUserServerList` reads that list once none of `serverUrls` had the blob, where the `ndk` version ignored it. A download checks that the bytes hash to the blob's sha256, and throws a `BlossomHashMismatchException` otherwise. A missing or empty server list throws a `BlossomNoServerListException` instead of a bare `Exception`.
 - Everything `Blossom` takes is optional: a read needs no `accounts`, `signerFactory` nor `getUserServerList`, and an operation that signs with a throwaway key throws a `StateError` without a `signerFactory`. It takes an `httpClient`, and `close()` ends the operations in flight and closes the client it made itself.
 - Every operation of `Blossom`, `Files` and `BlossomRepository` takes an `abortTrigger`, which ends that operation alone with a `RequestAbortedException`, as `abortPending()` ends them all.
 - `Blossom.uploadBlobFromStream` and `Files.uploadFromStream` upload what a function reads, on every platform, such as a file the app picked. On the web, `uploadBlobFromFile` no longer opens a file picker of its own, which kept the first file picked for a path and asked again for each server: a browser has no file paths, so it fails with an `UnsupportedError`.
 - A call whose `serverUrls` or `targetServerUrls` name no server url `BlossomServerUrl.tryParse` accepts throws a `BlossomNoServerListException`, where an upload threw a `BlossomAuthUnavailableException` naming a throwaway key, or under `AuthPolicy.never()` uploaded nowhere. A read given `pubkeyToFetchUserServerList` too reads that list at once.
 - `UploadStrategy.mirrorAfterSuccess` mirrors to the other servers at once rather than one after the other, so `completedUploads` lists the mirrors in the order they finish.
 - `Blossom.kBlossom` became `kBlossomAuthorization`, and `Files.download`, `downloadToFile` and `checkUrl` take `pubkeyToFetchUserServerList` instead of `pubkey`, as `Blossom` does.
 - `mirrorToServers` throws a `FormatException` for a url without a sha256, and `publishUserServerList` an `ArgumentError` for an empty list and a `StateError` when nobody is logged in, where they threw an `Exception` or a `String`.
 - `BlobDescriptor.uploaded` is a `DateTime?`, null when the server did not give it rather than the time it was read, and `size` is null when it is missing rather than 0. A field of the wrong type is dropped rather than thrown on.
